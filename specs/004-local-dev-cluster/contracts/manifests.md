# Contract: base manifests (E02)

Enforced offline by `test/contract/manifests_test.go`.

1. `deploy/base/kustomization.yaml` lists every `*.yaml` in `deploy/base/`.
2. Namespaces `can-system`, `can-data`, `can-portal`, each with `pod-security.kubernetes.io/enforce`; `can-portal` is `restricted`, `can-system` is not; `kube-system` is never declared.
3. Each platform namespace has a NetworkPolicy `default-deny` (empty `podSelector`, `Ingress`+`Egress`, no rules) and `allow-dns` (to `kube-dns` in `kube-system`, port 53).
4. Named allows (the module template also carries `allow-ingress-from-traefik` and `allow-ingress-from-can-core`, since default-deny blocks module UIs and webhooks otherwise): `allow-ingress-from-traefik` (can-system, can-portal); `allow-module-api-from-modules` (can-system, can-core pods, from namespaces of kind module/portal); `allow-can-core-egress`; `allow-db-from-modules-and-core` (can-data, 5432/3306); portal egress to the module API.
5. No NetworkPolicy contains `0.0.0.0/0` except `allow-can-core-egress` (ports 6443/443 only).
6. Each platform namespace has a ResourceQuota and a LimitRange with default requests and limits. Base declares no workloads; any that appear must pin digests and set requests, limits and a securityContext.
7. `HelmChartConfig/traefik` (kube-system, `helm.cattle.io/v1`): `persistence.enabled`, ACME storage under `persistence.path`, `service.spec.externalTrafficPolicy: Local`.
8. `ConfigMap/coredns-custom` (kube-system): keys end in `.override`/`.server`; `admin.localtest.me` pinned before the wildcard `localtest\.me` rewrite to `traefik.kube-system.svc.cluster.local` with `answer auto`; alias to `can-core-api.can-system.svc.cluster.local`.
9. RBAC: `ServiceAccount can-system/can-core`. ClusterRole `can-core` (the only one behind a ClusterRoleBinding): namespaces get/list/watch/create, tokenreviews create, rolebindings get/list/watch/create, `bind` on `clusterroles/can-core-module`. Failing conditions: any cluster-scope grant of secrets, pods/exec, workload resources, namespaces update/patch/delete, or a `bind` without `resourceNames`. ClusterRole `can-core-module` (secrets, workloads, NetworkPolicies, quotas, pods read/exec, ...) is only bound by RoleBindings: base binds it in can-system and can-data, and `deploy/templates/module-rbac.yaml` binds it in each `mod-<id>` namespace. No `*`, no `escalate`/`impersonate`, nothing bound to `cluster-admin`, every binding subject is can-core; kube-system Role restricted by `resourceNames`. This is a reduced standing grant, not least privilege. Residual (RBAC cannot express), effectively cluster-admin for a compromised can-core until the E03 ValidatingAdmissionPolicy: can-core can bind `can-core-module` in any namespace (including kube-system) and create namespaces with relaxed pod-security labels; its kube-system Role can replace the Traefik `HelmChartConfig` (arbitrary chart values) and `coredns-custom` (DNS hijack). Also: any module namespace can reach every database in can-data (`allow-db-from-modules-and-core` selects namespaces, not modules); DB authentication is the only per-module barrier.
10. `deploy/templates/module-namespace.yaml`: Namespace labelled `can.dev/namespace-kind: module` with PSA enforce; `default-deny`; `allow-ingress-from-traefik`; `allow-ingress-from-can-core`; `module-egress` (DNS, can-core API, Traefik, can-data, internet except `${NODE_IP}/32`, `10.42.0.0/16`, `10.43.0.0/16`, `169.254.0.0/16`); LimitRange; ResourceQuota.
11. `dev/k3d.yaml`: `k3d.io/v1alpha5` Simple, name `companyinacan-dev`, pinned `rancher/k3s:v...` image, 1 server 0 agents, ports 80/443 on the loadbalancer, `--disable=metrics-server`, `--secrets-encryption`, Traefik not disabled, `wait: true`.
