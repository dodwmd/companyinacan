# deploy/files

Container build for the files module (`cmd/can-files`).

## Image

`Dockerfile` is a two-stage build: `golang` builder, then `gcr.io/distroless/static-debian12:nonroot`
(no shell, no package manager, uid 65532). The binary is static (`CGO_ENABLED=0`; SQLite is the
pure-Go `modernc.org/sqlite`). Because there is no `curl`, health probes use the binary itself:
`/can-files healthcheck -addr 127.0.0.1:8095`.

## Digest pinning

Both base images must be pinned by digest before a release build. The Dockerfile ships with
placeholders (`sha256:REPLACE_WITH_...`) so an unpinned build fails instead of silently using
a moving tag. Look the digests up, review them, and pass them as build args (or commit them):

```sh
crane digest golang:1.27                          # GO_IMAGE_DIGEST
crane digest gcr.io/distroless/static-debian12:nonroot   # DISTROLESS_DIGEST
```

## Runtime contract

| What | Value |
|---|---|
| Listener | `:8095`: the files API under `/v1` (bearer token) and the public share-link download `GET /s/{token}`. Expose only `/s/` through the ingress; `/v1` stays ClusterIP. `GET /healthz` needs no token; `GET /readyz` also checks the database and the blob backend |
| Data | `/data/files.db` (SQLite, WAL), `/data/staging` (uploads in flight, 0700, cleared at start) and, with the local backend, `/data/blobs` (0700): one persistent volume |
| Config | `/etc/can-files-config/files.yaml` (`CAN_FILES_CONFIG`); see `modules/files/chart/values.yaml` |
| Secrets | env `CAN_FILES_API_TOKEN` and `CAN_FILES_LINK_SECRET` (32+ characters, generated by can-core) and optionally `CAN_FILES_RESTORE_TOKEN` (restore-only purge credential), the keyring file (`keyring_path`, mode 0400, 0440 or 0600), and with `backend.type: s3` the env `CAN_FILES_S3_ACCESS_KEY_ID` and `CAN_FILES_S3_SECRET_ACCESS_KEY` |
| Commands | `serve`, `check-config`, `healthcheck`, `verify-audit`, `rotate-keys` (re-seal names and descriptions under the newest key), `sweep` (one retention pass), `version` |
| Idle RAM | measured locally, see `specs/034-files/research.md` R9; target 28 MB with the web UI (`specs/050-files-ui/research.md` R2), limit 64 MB. Uploads and downloads are streamed |
| Root filesystem | read-only works: only `/data` is written |

SIGTERM triggers a graceful shutdown within 20 seconds; set `terminationGracePeriodSeconds` to at
least 30.

The image has **not** been built in CI or run on a cluster; the Dockerfile is a fragment with digest
placeholders, and `scripts/check-image-pins.sh` fails a release build until they are pinned.
